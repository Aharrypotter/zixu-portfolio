设计与实现 / FlagLang

把线程与内存映射，变成可组合的语言能力

问题
算子实现需要协调逻辑索引、线程、寄存器与内存，映射关系难以统一表达和检查。
我的工作
参与 GPU Kernel DSL 与 Layout 研发，推进布局组合、共享内存表达和降级；以真实算子检验语言接口。
结果与边界
补充行统计及归约后表达式组合，在 H20 完成限定输入场景的编译与数值验证。这是团队研发中的个人贡献，不等同于全部能力已上游发布。
布局设计、实现与证据 ↗

性能工程 / cuLA

让循环状态留在 GPU 寄存器，减少数据搬运

问题
Lightning Attention 的分块计算需要持续传递状态，流水线与状态管理同时影响性能和正确性。
我的工作
独立实现 Hopper prefill 流水线，使 FP32 状态跨 chunk 常驻寄存器，并处理变长输入、初始和最终状态及尾块。
结果与边界
PR #111 已合并。H20、BF16、D=128、chunk=64 的 34 组主测试，相对 FLA 几何平均加速 2.89×；这是算子测试结果，不是端到端服务吞吐。
查看已合并的实现与评审 ↗

SYSTEMS ENGINEERING / EDGEKV

让 KV Cache 压缩，从算法走进运行时

问题
压缩能省存储，但重建与数据搬运可能让推理更慢。
我的工作
推进 BlockSVD 参考、llama.cpp / GGML 集成、后端持久因子池与增量上传，并开发 Hexagon 计算路径。
交付与验证
CPU smoke 验证 56 次容量内更新均只上传新增块；HTP 重建在固定 v79 仿真输入上与独立参考对齐。模型质量、局部内核和完整推理分别验证。
看系统设计、关键取舍与实验结果 ↗

开源交付 / Apache TVM

从真实模型导入失败，追到算子语义边界

问题
模型能够导出，不代表编译器能够正确导入；动态形状、量化和边界输入容易暴露语义差异。
我的工作
修复 ONNX、TFLite 等前端的算子映射与语义问题，覆盖标量 QDQ、PRelu、CastLike 和动态 k Trilu 等具体场景，提交上游评审。
结果与边界
截至 2026-09-14 的核验记录，Apache TVM 已合并 34 个 PR。每条贡献保留原始改动与验证线索；数量是快照，不作为实时统计。
